# ПрактикБот

**Программный комплекс сопровождения учебной и производственной практики студентов среднего профессионального образования.**

ПрактикБот реализован в формате чат-бота для мессенджера MAX. Система предназначена для организации взаимодействия студентов, преподавателей, представителей работодателя и администрации при подготовке, передаче и проверке материалов по практике.

**Публичная ссылка на проект в MAX:** [ПрактикБот — открыть в MAX](https://max.ru/idea_fiks_83_boy)  
Перед передачей материалов необходимо проверить ссылку в карточке бота MAX и убедиться, что она открывает действующий экземпляр проекта.

## 1. Функциональные возможности

### Роли пользователей

| Роль | Основные возможности |
|---|---|
| Студент | Регистрация по учебной группе и ФИО; получение индивидуального кода для привязки сотрудников; заполнение отчётов и дневников; передача материалов на проверку; получение оценок и комментариев; использование ИИ-помощника. |
| Преподаватель | Привязка к студентам; просмотр отчётов и дневников закреплённых студентов; проверка работ и выставление оценок; комментарии; управление учебными группами и их специальностями; настройка каталога практик; ручные напоминания о заполнении дневников; обработка ранее созданных заявок; использование ИИ-помощника. |
| Работодатель / наставник | Привязка к студентам; просмотр материалов закреплённых студентов; подтверждение прохождения практики и добавление комментариев; использование ИИ-помощника. |
| Администратор | Общая статистика; управление группами; экспорт сводных данных в Excel; просмотр и обработка заявок, созданных в предыдущих версиях; использование ИИ-помощника. |

### Учёт практики

- Поддерживается маршрут из восьми базовых практик — ПМ.01–ПМ.08.
- Следующая практика открывается после оценки предыдущей преподавателем.
- Для практик, предусмотренных конфигурацией проекта, студент заполняет структурированный отчёт из четырёх разделов.
- В разделы 1, 2 и 4 допускается добавление файлов; раздел 3 предназначен для текстового заполнения.
- Для дневниковых практик предусмотрены дата и описание выполненной работы. Повторная запись за ту же дату обновляет существующую запись, а не создаёт дубликат.
- Преподаватель и наставник получают доступ только к студентам, с которыми установлена связь в системе.
- Система сохраняет статусы работ, оценки, комментарии и сведения о действиях проверки.

### ИИ-помощник YandexGPT

ИИ-помощник доступен из пользовательских меню и выполняет следующие задачи:

- преобразует краткие описания выполненных работ в формальные формулировки для дневника практики;
- предлагает код профессиональной компетенции из локального справочника, если соответствующие данные доступны;
- отвечает на общие вопросы по оформлению отчётов, дневников и организации практики.

ИИ-помощник не заменяет преподавателя, не выставляет оценки и не подтверждает допуск к практике. Ответы формируются на основе общих инструкций и переданных проекту справочных данных; поиск по отдельной базе методических документов колледжа в текущей версии не реализован.

### Дополнительные функции

- Авторизация преподавателей, работодателей и администраторов по одноразовым кодам.
- Срок действия кода авторизации — 24 часа; код используется однократно.
- Защита от частого ввода неверных кодов.
- Управление учебными группами и специальностями.
- Ручная отправка напоминаний студентам, закреплённым за преподавателем.
- Экспорт отдельных материалов в TXT и сводных данных в XLSX.
- Передача вложений MAX преподавателю или наставнику при просмотре соответствующей работы.

## 3. Состав репозитория

```text
ПрактикБот/
├── main.py                  # Основной сценарий чат-бота и взаимодействие с MAX API
├── ai_assistant.py          # Интеграция YandexGPT
├── security.py              # Авторизация сотрудников и управление кодами доступа
├── report_structure.json    # Настройки сценариев и структуры практик
├── pm_competencies.json     # Справочник профессиональных компетенций
├── requirements.txt         # Зависимости Python с зафиксированными версиями
├── Dockerfile               # Инструкция сборки Docker-образа
├── docker-compose.yml       # Конфигурация сборки и запуска контейнера
├── .dockerignore            # Исключения из контекста Docker-сборки
├── .gitignore               # Исключения для Git
├── .env.example             # Образец конфигурации без секретных значений
├── tests/
│   ├── test_bot_logic.py    # Проверки основной логики
│   └── test_security.py     # Проверки механизмов безопасности
```

Файл `.env` и рабочее хранилище `bot_data.json` в репозиторий не включаются. При первом запуске хранилище создаётся автоматически. В Docker данные сохраняются в локальной папке `data/`.

## 4. Требования к запуску

Для локального запуска необходимы:

- Python версии 3.10 или выше;
- доступ к сети Интернет;
- зарегистрированный и доступный чат-бот MAX;
- токен доступа MAX Bot API;
- API-ключ Yandex AI Studio и идентификатор каталога Yandex Cloud для работы ИИ-помощника.

Для контейнерного запуска дополнительно необходимы Docker Engine и Docker Compose V2. На Windows допускается использование Docker Desktop.

## 5. Настройка конфигурации

1. Скопируйте файл `.env.example` в `.env`.
2. Откройте `.env` и укажите реальные значения параметров.
3. Не публикуйте `.env`, не добавляйте его в Git и не передавайте в общедоступных архивах.

Основные переменные:

| Переменная | Назначение | Обязательность |
|---|---|---|
| `BOT_TOKEN` | Токен чат-бота MAX. | Да |
| `YANDEX_API_KEY` | API-ключ Yandex AI Studio. | Для функций ИИ |
| `YANDEX_FOLDER_ID` | Идентификатор каталога Yandex Cloud, к которому выдан доступ ключу. | Для функций ИИ |
| `YANDEX_BASE_URL` | Адрес совместимого API YandexGPT. По умолчанию `https://ai.api.cloud.yandex.net/v1`. | Нет |
| `YANDEX_MODEL` | Имя модели или полный URI модели. По умолчанию `yandexgpt/latest`. | Нет |
| `YANDEX_TIMEOUT` | Время ожидания ответа модели в секундах. | Нет |
| `YANDEX_MAX_RETRIES` | Количество повторных попыток запроса. | Нет |
| `SECURITY_ENABLED` | Включение авторизации сотрудников. Для рабочего режима — `true`. | Нет, по умолчанию включено |
| `TESTING_AUTH_MODE` | Тестовый обход авторизации. Для рабочего режима — `false`. | Нет, по умолчанию выключено |
| `GROUPS` | Необязательный список групп через запятую. | Нет |
| `DATA_FILE` | Путь к JSON-хранилищу. | Нет |
| `FLOW_FILE` | Путь к файлу структуры сценариев. | Нет |

Для рабочего экземпляра необходимо установить `SECURITY_ENABLED=true` и `TESTING_AUTH_MODE=false`. Не используйте тестовый режим при публичной демонстрации или эксплуатации.

## 6. Локальный запуск в Windows

Выполните команды PowerShell из корневой папки проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Создайте `.env` на основе `.env.example`, заполните необходимые параметры и запустите приложение:

```powershell
python main.py
```

Для остановки приложения нажмите `Ctrl+C` в окне терминала.

### Выпуск кодов доступа для сотрудников

Код выпускается локальным оператором от имени проекта. Перед изменением хранилища рекомендуется остановить работающий экземпляр бота, чтобы исключить одновременную запись в JSON-файл.

```powershell
python security.py issue teacher
python security.py issue employer
python security.py issue admin
```

Команда выводит одноразовый код. Передайте его соответствующему сотруднику по согласованному защищённому каналу. Не размещайте действующие коды в репозитории и общедоступных документах.

Дополнительные команды:

```powershell
python security.py list
python security.py revoke AC-XXXXXXXX
```

`list` отображает сведения о выпущенных кодах, `revoke` отзывает неиспользованный код по его идентификатору.

## 7. Сборка и запуск Docker-контейнера

### Сборка Docker-образа

Из корневой папки проекта выполните:

```powershell
docker build -t praktikbot:latest .
```

Команда формирует локальный образ `praktikbot:latest` на основании `Dockerfile` и устанавливает зависимости из `requirements.txt`.

### Запуск через Docker Compose

Предварительно должен быть создан и заполнен файл `.env`. Затем выполните:

```powershell
docker compose up --build -d
```

Docker Compose соберёт образ, создаст контейнер и запустит бота в фоновом режиме. Пользовательские данные будут сохраняться в папке `data/` рядом с `docker-compose.yml` и останутся доступными после пересоздания контейнера.

### Просмотр журнала работы

```powershell
docker compose logs -f praktikbot
```

### Остановка контейнера

```powershell
docker compose down
```

Обычная команда `docker compose down` не удаляет папку `data/`. Не удаляйте её, если необходимо сохранить сведения о студентах, отчётах, дневниках, оценках и авторизациях.

### Выпуск кода доступа внутри контейнера

```powershell
docker compose exec praktikbot python security.py issue teacher
```

Вместо `teacher` можно указать `employer` или `admin`.

## 8. Проверка корректности

Перед передачей исходного кода рекомендуется выполнить компиляционную проверку и автоматические тесты:

```powershell
python -m py_compile main.py ai_assistant.py security.py tests/test_bot_logic.py tests/test_security.py
python -m unittest discover -s tests -v
```

В составе передаваемого комплекта проверено **68 автоматических тестов; все 68 завершились успешно**. Проверки охватывают регистрацию, роли, последовательность открытия практик, обработку отчётов и дневников, ограничения доступа, экспорт и операции с кодами авторизации.

Автоматические тесты используют тестовые данные и имитацию отдельных ответов внешних сервисов. Они не заменяют проверку фактического взаимодействия с MAX и Yandex Cloud с рабочими учётными данными.

## 9. Ограничения текущей версии

1. Основное хранилище — JSON-файл. Миграция на PostgreSQL или SQLite в данный комплект не входит.
2. Получение событий MAX реализовано через Long Polling. Webhook с публичным HTTPS-адресом в текущем комплекте не настроен.
3. Дополнительные практики и дополнительные разделы отчёта присутствуют в административных настройках, но их полный маршрут заполнения студентом не подключён к основному процессу.
4. В переданном справочнике компетенций отсутствует отдельный перечень ПК для ПМ.08. Подбор компетенции для этой практики может быть недоступен.
5. Ответы ИИ не привязаны к загруженной базе локальных методических документов колледжа. При необходимости такую базу следует подключить и отдельно проверить.
6. Напоминания о дневниках отправляются вручную; автоматический планировщик не включён.
7. Для выгрузки реализованы TXT и XLSX. Генерация итоговых документов PDF и DOCX не входит в текущую версию.

Указанные ограничения следует учитывать при демонстрации и дальнейшей разработке. Наличие настроек или каталога в интерфейсе не означает, что соответствующая функция полностью подключена к пользовательскому маршруту.

## 10. Требования информационной безопасности

- Храните `BOT_TOKEN` и `YANDEX_API_KEY` только в переменных окружения или локальном файле `.env`.
- Не включайте `.env`, `bot_data.json`, папку `data/` и виртуальное окружение `.venv/` в публичный Git-репозиторий.
- Не передавайте реальные персональные данные студентов вместе с исходным кодом.
- Используйте одноразовые коды для регистрации сотрудников и передавайте их адресатам по защищённому каналу.
- Регулярно создавайте резервные копии рабочего JSON-хранилища и ограничивайте доступ к ним.
- При подозрении на раскрытие токена отзовите его в соответствующей панели управления и выпустите новый.
